# 明暗主题由应用自绘并立即生效

## Status

accepted

## Context

界面颜色此前是 `main.py` 里的一个模块级常量 `COLORS`，控件在构造时直接读取，所以更换颜色必须重建控件；同时托盘右键菜单是 Win32 原生菜单，颜色由系统决定。需要在不引入任何第三方依赖、不改变 tkinter 技术栈的前提下，支持亮色、暗色与跟随系统三种主题模式，并提供预设与自定义配色。

## Decision

主题状态由三个配置项描述：`theme_mode`（system / light / dark）、`theme_preset`（预设 id，含 `custom`）、`theme_custom`（亮暗两个背景色与派生所用的强调色来源）。主题逻辑独立到 `theme.py`，`main.py` 只持有一份可变的语义色字典。

1. 语义色按用途命名，预设只覆盖亮暗两套取值；状态色不随预设变化，只在明暗之间切换。
2. 自定义配色只让用户填亮、暗各一个背景色，主文字按对比度自动取深或浅，强调色沿用进入自定义前的预设，对比不足时自动加深或提亮。
3. 跟随系统靠每 5 秒读一次注册表 `AppsUseLightTheme` 实现，仅在跟随系统模式下保留定时器；不使用 Win32 消息广播，避免改动托盘消息循环。
4. 切换主题立即生效：主窗口保留根窗口，销毁并重建内部控件；已打开的备注管理与关于窗口按原位置自动重开；设置窗口原地重建并保留输入值与当前页签。
5. 暗色下 ttk 切换到 `clam` 主题并逐控件配置样式，亮色保持 `vista` 原生外观；窗口标题栏通过 `DwmSetWindowAttribute` 变暗，失败时静默忽略。
6. 顶部条亮色下沿用强调色填充，暗色下改用卡片色表面加强调色文字，避免暗色界面里出现高饱和色带。
7. 托盘右键菜单不提供主题入口，主题只在设置的外观页修改；原生菜单跟随系统。

## Considered Options

- 主题改动只在下次启动生效：实现最省事，但用户在设置里改完看不到效果，等于把验证成本推给用户。
- 依赖第三方主题库（如 sv-ttk）：观感更完整，但违背本项目零外部依赖的约束。
- 托盘菜单加主题子菜单：需要扩展 `tray_v2.set_menu_items` 支持原生子菜单，收益低且让菜单更拥挤。

## Consequences

- 新增的配置项必须与旧 `config.json` 兼容：缺失时回落到跟随系统加默认预设。
- 设置对话框保存时必须基于原配置合并，不能只写表单字段，否则主题项会被清掉。
- 主窗口重建是切换主题的唯一路径，任何依赖控件实例的引用（如状态点、进度条、搜索变量）都要在重建后重新绑定。
- 暗色下的原生消息框、托盘菜单不受应用控制，属于已知边界。
