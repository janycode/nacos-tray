# 主窗口提供表格与卡片两种视图，置顶按服务名记录

## Status

accepted

## Context

主窗口此前只有一种服务列表：每个实例占一行，服务名随实例重复出现。用户日常只盯少数服务（例如 om），既希望快速定位它们，又希望有更直观的展示方式；同时选中行使用强调色整行填充，会盖掉在线/离线状态色，观感生硬。项目约束是零外部依赖，界面只能用 tkinter/ttk 自绘。

## Decision

1. 视图模式作为配置项 `view_mode`（table / card）持久化到 `config.json`，顶部条提供"表格 | 卡片"切换，切换后立即重建主窗口内容。
2. 表格视图保持"每个实例一行"，新增最左星标列；同一服务的每一行显示同一颗星，点任意一行切换整个服务的置顶状态。
3. 卡片视图由 Canvas + Frame 手绘，一张卡片对应一个服务，卡内列出该服务的全部实例。卡片按服务名在容器中就地更新，仅当服务集合或排序变化时才重新 grid，避免每次轮询重建控件。
4. 置顶是单一概念，按服务名存入 `config.json` 的 `pinned_services`，表格、卡片与托盘弹窗都按"置顶优先、其余按服务名"排序；置顶的服务暂时从 Nacos 拉不到时保留记录。
5. 卡片视图点击实例弹出确认后上/下线，与托盘弹窗一致；右键菜单在实例行作用于该实例，在卡片空白处只保留与实例无关的项。
6. 表格选中行改为强调色与卡片色按 18% 混合的柔和底色，不再覆盖标签的前景色，在线绿/离线红保持可见。
7. 按钮图标使用 Windows 自带的 Segoe MDL2 Assets 字形，检测不到字体时回退为纯文字；主窗口绑定 F5 刷新。

## Considered Options

- 收藏与置顶分两级：表达力更强，但用户只需要"把常看的服务排最前"，两级会增加心智负担。
- 用 emoji 做图标：无需字体检测，但不同 Windows 版本的观感差异大，且与文字基线不齐。
- 卡片视图只读：实现更省事，但用户盯卡片时无法顺手处理上下线，仍需切回表格。
- 托盘弹窗也做卡片：弹窗定位是紧凑速览，卡片会让它变宽变高，收益低。

## Consequences

- `config.json` 新增 `view_mode` 与 `pinned_services`，旧配置缺失时分别回落到 table 与空列表。
- 主题切换会重建主窗口，卡片视图的控件状态全部重新生成；视图模式本身存在配置里，因此重建后保持不变。
- 卡片视图多实例卡片上的上下线、免打扰仍按实例粒度处理，空白处右键禁用这些项，避免误操作。
- 卡片视图的滚动依赖根窗口的鼠标滚轮绑定，仅在指针位于卡片画布内时接管。
