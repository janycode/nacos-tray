# 卡片实例行提供免确认的快捷上下线

## Status

accepted

## Context

卡片视图里，实例行的主点击行为是弹出确认框后上下线。用户频繁切换个别实例时，每次都要移动鼠标到行内、点击、再确认，路径较长。表格视图保持现有确认式操作不变，只有卡片视图需要更快的入口。

## Decision

1. 鼠标悬停实例行时，在行最右侧显示一个与当前状态互斥的操作：在线显示“下线”，离线显示“上线”。
2. 快捷操作立即执行，不弹确认框；点击整行仍保留原有确认流程。
3. 点击后实例行进入“处理中”状态，后台调用 Nacos 更新接口并静默拉取服务列表，不展示进度条或成功气泡；失败时才弹错误气泡。
4. 悬停实例行时隐藏“最近上线时间”，把最右侧空间让给快捷按钮；移出后恢复。
5. 实例行悬停使用强调色 10% 混入卡片色的浅底色；卡片任一区域悬停时边框变为强调色 1px。
6. 快捷按钮只显示图标，颜色区分上线/下线；悬停图标时边框变为强调色，卡片与托盘弹窗保持一致。
7. 托盘右键弹窗的实例行也在右侧常显同一套快捷图标；点击后先关闭弹窗，再执行快捷上下线。

## Considered Options

- 快捷操作也弹确认：更安全，但失去“快捷”的意义；需要确认时仍可点击整行。
- 只显示图标不显示文字：更省空间，但上线/下线语义不够直观。
- 悬浮时保留最近上线时间并在右侧追加按钮：行内过于拥挤，窄卡片会挤压 IP。
- 只在表格提供快捷按钮：表格列宽有限，且用户明确只要求卡片视图。

## Consequences

- 误点快捷按钮会立即改变实例状态，需要依赖 Nacos 的上下线能力恢复。
- 快捷操作期间同一实例的按钮显示“处理中”，阻止重复点击。
- 快捷操作不触发上线/下线的气泡通知，状态栏和服务计数仍会更新。
- 悬停态依赖鼠标事件；触屏或无鼠标环境下只能使用整行点击的确认流程。
