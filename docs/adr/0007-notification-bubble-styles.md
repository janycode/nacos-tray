# 气泡样式四选一并与主题色调联动

## Status

accepted

## Context

现有通知使用 Windows 系统气泡（`Shell_NotifyIcon` + `NIF_INFO`），样式完全由系统决定，无法与应用的配色预设联动。用户要求保留系统通知作为默认外观，另提供三种更美观的样式，并跟随应用当前的颜色色调。

## Decision

1. 气泡样式是一个外观配置项，取四个值：默认通知、卡片浮窗、强调渐变、极简横幅。默认通知沿用现有系统气泡，其余三种为 tkinter 自绘窗口。
2. 自绘气泡只使用当前生效主题的语义色（明暗模式 + 配色预设或自定义强调色），事件语义色固定用于状态条与状态点（成功绿、失败红、警告橙、信息蓝）；不提供独立的通知配色。
3. 所有来源的通知统一进入通知中心排队：同屏最多 3 条；同一次轮询内不超过 3 条时逐条展示，超过 3 条合并为一张摘要卡；默认通知样式仍逐条交给系统排队。
4. 自绘气泡固定在主屏右下角、避开任务栏、自下而上堆叠；停留 8 秒，悬停暂停，点击跳转（Nacos 事件打开主窗口，Jenkins 事件打开构建页）。
5. 极简横幅只显示状态点、标题与单行正文；卡片浮窗与强调渐变可显示多行正文与提交列表。

## Considered Options

- 只保留系统通知：改动最小，但无法实现美观样式与色调联动。
- 三种自绘样式各自定义配色：与「外观」主题脱节，用户要维护两套颜色。
- 引入第三方 Toast 库：项目坚持零外部依赖，且第三方库同样难以跟随主题语义色。

## Consequences

- 自绘气泡必须在 tkinter 主线程创建与销毁，后台轮询通过 `after` 回主线程。
- 三种自绘样式只支持 Windows（依赖透明色与置顶窗口），与项目现有平台约束一致。
- 默认通知样式下，正文受系统气泡长度限制，需要截断；自绘样式不受此限制。
