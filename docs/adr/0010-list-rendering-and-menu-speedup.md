# 列表渲染与浮层构建提速

## Status

accepted

## Context

读码得到的全量重建路径（均未做运行期计时，属静态结论）：

| 位置 | 现状 |
|---|---|
| `_switch_source`（`main.py:3258`） | 销毁 `_list_frame` 全部子控件后 `_build_list_view` 重建，卡片状态全部丢弃 |
| `_update_table`（`main.py:3007`）、`_update_jenkins_table`（`main.py:3309`） | 每轮 `delete` 全部行再逐行 `insert` |
| `_build_menu`（`main.py:2756`） | 每次轮询 / 状态变更都重建 Win32 原生菜单（`tray_v2.py:273`），内容不变也重建 |
| `_show_service_list_popup`（`main.py:2891`） | 每次右击新建 `ServiceListPopup` 并构建全部行 |
| `_open_items_menu`（`main.py:4350`） | 每次调用新建菜单 `Toplevel` |
| `_apply_theme`（`main.py:2571`）/ `_rebuild_root_ui`（`main.py:3151`） | 销毁 root 下全部 UI 后重建 |

需求要求：点击唤出要快、切换要顺滑；并明确**不做埋点测量，直接按已知路径改**。

## Decision

分两批实施，每批独立自测后再进下一批。

### 第一批：直接改善点击手感

1. **来源切换改为容器互换**：Nacos 与 Jenkins 各持有一个常驻容器（`_nacos_container` / `_jenkins_container`），首次构建后缓存；切换只做 `pack_forget` / `pack`（或 `grid` 等价操作），保留滚动位置、选中项与卡片展开状态。目标：切换 ≤ 50ms 且无白屏闪烁。
2. **托盘弹窗单例复用**：`ServiceListPopup` 由「每次新建」改为「单例 + 打开时按需刷新行数据」；配合 ADR-0009 的圆角与淡入。
3. **右键菜单单例复用**：保留一个常驻菜单 `Toplevel`，打开时只更新条目与目标对象，不再重建窗口。

### 第二批：后台效率

4. **表格增量刷新**：`_update_table` / `_update_jenkins_table` 改为按键 diff。行键：Nacos = `(服务名, 实例 IP)`，Jenkins = Job 全名。对比单元格文本与标签，只对变化的行调用 `tree.item(...)`，新增行 `insert`、消失行 `delete`；排序变化通过移动既有行而非整表重排。目标：轮询不再引起整表重绘抖动。
5. **托盘菜单内容指纹**：`_build_menu` 生成菜单项指纹（服务名 + 在线态 + 置顶 + Jenkins 行摘要），与上次比对，一致则跳过 `set_menu_items`。目标：内容不变时零重建。
6. **主题切换局部化（可选，成本最高）**：把 `_rebuild_root_ui` 的「销毁重建」改为「原地换色 + 仅重建真正依赖主题的控件」。若实施成本过高，本项可单独延后，前两批已覆盖主要痛点。

### 验收标准

- 来源切换：无可见白屏，切换耗时 ≤ 50ms。
- 托盘弹窗：从右击到首帧可见 ≤ 30ms（不含淡入动画），且不随服务数量线性变慢地重建窗口。
- 轮询刷新：表格行数较大时无明显抖动；离线/在线变化只更新对应行。
- 原生托盘菜单：连续两次相同状态的轮询只构建一次菜单。
- 右键菜单：连续对不同行打开，窗口实例复用（不累积 `Toplevel`）。

## Considered Options

- **先埋点测量再改**：用户明确否决，直接改。
- **只把 destroy-rebuild 换成 show/hide**：能解决切换与弹窗，但表格每轮重排与原生菜单重建仍在，后台路径依旧浪费。
- **改用虚拟列表 / 只渲染可视行**：tkinter `Treeview` 不支持，需自绘整套表格，改动过大且触碰核心展示，超出本次范围。

## Consequences

- 表格 diff 是最容易引入显示错乱的一项：需要明确的行键唯一性约束、单元格对比顺序，以及"某行从离线变在线"时状态列与标签同时更新。
- 容器互换后，两个来源的视图会同时驻留内存，占用略增；但两者的轮询线程本就独立运行，无额外线程成本。
- 单例复用要求关闭路径必须彻底（程序退出、主题切换、窗口重建时都要销毁单例），否则会残留旧主题颜色的浮层。
- 本次不改 `_switch_source` 的语义（仍是"同一时刻只显示一个来源"），只改实现方式。
